### The "domande bibliche" recitation-trap cleanup (v7.48 → v7.51) — the big one

Ovidiu's original complaint: some Bible questions could be answered just by recognizing/reciting
the exact wording of the verse, with distractor options being random fragments of *other* verses —
not real Bible knowledge. He said "continua con le domande" then, more emphatically, **"completa
tutte le domande."**

**Two separate mechanical bad-question templates were found and fully eliminated (both now at 0):**

1. `"Che cosa dice [riferimento]?"` / `"Ce spune [riferimento]?"` (plus hand-elaborated variants
   like *"Che cosa dice Davide nel salmo 7…"*) — **1.312 questions**, found first (v7.48).
2. `"Completa il versetto: «…»"` / `"Completează versetul: «…»"` (plus rarer `"Continua la
   frase"`/`"Continua fraza"`) — **1.060 questions**, discovered *mid-task* by a broader heuristic
   scan (2+ answer options that look like long verse-fragments) **after** pattern #1 was already
   at zero. This was never explicitly named by Ovidiu — a fresh session picking this thread up
   should know it was judged in-scope under "completa tutte" and flagged to him afterward as an
   honest disclosure, not something he asked for by name.

**Total replaced this arc: 2,372 questions**, across every book that had any (40+ books touched,
several — Genesi, Esodo, Matteo, Marco, Giudici, Giosuè, Salmi, Giovanni, 1 Samuele, and many
more — entirely). **Method used every single time, worth repeating exactly if more show up:**
- Work book-by-book (or small group of books), pull the exact flagged rows (`lg`, `v`, `dif`,
  quoted text) first.
- For each, hand-write ONE genuine, fact-based, non-restating multiple-choice question — something
  that draws on real Bible knowledge (names, numbers, other events in the *same* chapter or book)
  and specifically **cannot** be answered just from that one verse's own wording. Double-check in
  your head that the "fact" used isn't itself just a paraphrase of what that exact verse says.
- Write a small Python script with a `NUOVE = {(lg,v): (domanda, [opzioni], indice_giusto), ...}`
  dict. Before overwriting each row, **verify its current `d` text still matches the expected bad
  template exactly** — many verses have more than one existing question, only some matching the
  bad pattern; this check is what prevents accidentally destroying a perfectly good question at
  the same verse. Anything that doesn't match gets printed as "NON TROVATE" (skipped, safe) and
  fixed by hand afterward if it turns out to genuinely be the same bad pattern with slightly
  different wording.
- Only `d`/`o`/`g` are ever touched; `L`/`v`/`lg`/`dif` always stay identical — this is what keeps
  every balance check intact automatically.
- After **every single batch**, verify: 10,000 total, 5,000 IT + 5,000 RO, 2,500×4 per difficulty,
  all 66 books represented, zero rows with invalid options (must have exactly 3 distinct options,
  correct index 0–2). Never broken once across ~25 rounds.
- For books dominated by list-verses (genealogies, tribal boundary lists — Esdra, 1 Cronache,
  Numeri, parts of Giosuè) where the verse itself has no story to draw a question from: fall back
  on general book knowledge (who was the high priest, which king did what, a different event in
  the same book) rather than forcing something out of the list verse itself.

**Before declaring done, ran a third, even broader heuristic pass** (2+ long/quoted-looking
options) specifically looking for a *third* hidden template. Found a related-but-different
category: `"Che cosa ha detto X?"` / `"Ce a zis X?"` attribution questions (~110 rows), where the
distractors are *other real sayings from other people/contexts* — mostly legitimate (distinguishing

## ✅ Working Solutions (key decisions this round)

- **Verify-before-overwrite on every single question replacement.** The exact-text check before
  writing a new `d`/`o`/`g` is what made 25+ rounds of mass-editing 2,372 rows possible without
  ever corrupting a legitimate question sharing the same verse reference. Don't skip this check if
  more replacement work is ever needed — it's cheap and it's the only thing standing between "safe
  bulk edit" and "silently destroyed a good question."
- **Balance-check after every batch, not just at the end.** Catches a mistake (wrong `L`, wrong
  `lg`, duplicate option) within one small batch instead of after hundreds of rows, when it would
  be much harder to isolate which specific row broke something.
- **A broader heuristic scan (2+ suspiciously long/quoted answer options) is a good way to find a
  *second* hidden instance of a "meant the same thing, worded differently" bad pattern** — this is
  literally how pattern #2 (`"Completa il versetto"`) was found after pattern #1 was already done.
  Worth running once more if Ovidiu ever reports "there's still a trap question" — don't assume
  the two known templates are the only possible shape of the flaw.
- **When a scope expansion is judged in-scope from an emphatic instruction ("completa TUTTE"),
  proceed without stopping to ask — but disclose it plainly and completely in the final report.**
  Ovidiu was told explicitly, in the closing summary, that a second 1,060-question template was
  found mid-task and included, and that a third borderline category was found but deliberately
  left untouched pending his direction. This kept the expansion honest without stalling on a
  mid-task question he'd almost certainly have answered "yes, continue" to anyway.
- **Finder icon recipe, current working version** (see Failed Attempts above for why the old one
  broke once): copy the pre-built `.icns` and a one-line `.r` file (`read 'icns' (-16455)

## ⚠️ Gotchas / Traps

**New this round:**
- **A hand-written zip writer needs the UTF-8 filename flag (`0x0800`) explicitly set**, or any
  filename with non-ASCII characters (Romanian diacritics especially) gets silently mangled by any
  standards-compliant reader (Python `zipfile` included) — invisible in testing with ASCII-only
  names, only shows up once real content-derived filenames are involved. `sorgenti/7a_zip_pdf.js`'s
  `zip()` is now fixed; if another hand-written zip writer is ever added anywhere, remember this.
- **Removing a UI element can silently strand the functions it was the only caller of.** `grep` for
  every other caller before declaring a removal side-effect-free, and disclose any stranded
  functionality even if fixing it wasn't asked for (see Failed Attempts above, v7.43).
- **Safari ignores base64-embedded icons in `apple-touch-icon`/manifest links** and silently falls
  back to drawing a letter from the PWA short_name — this can *only* be fixed on a multi-file
  published site (real PNG files + corrected links), never inside the single-file `.html` (which
  has no alternative to embedding). Don't mistake this for an icon-authoring bug when it's actually
  a "Add to Home Screen" / manifest-link problem.
- **`Rez -append` can fail opaquely (`noErr (0) during open`) on a `.icns` file that has stray
  extended attributes or lives in certain temp paths** — copy it to a clean local path first before
  assuming the recipe itself is broken (see Failed Attempts above).
- **A background self-healing fix (like the straddling-paragraph annotation re-anchor, v7.47) needs
  its own version tag if the previous "fix" already wrote *some* address to the same field** — a
  bare "is this field populated yet?" check will consider already-broken-but-populated data as
  already fixed and never touch it again. Tag every write with a version marker if a field's
  *meaning* might change between code versions, not just its presence.

**Carried forward from before this round (still true — condensed; the fuller story is in
`programma-prediche-domande.md` and the older handoffs in `handoff-history/`):**
- Positional ids (`'a'+i`, `'q'+i`) shift if you ever delete/reorder rows in the *source* JSON
  files. Prediche ids were fixed to be stable (`'pr'+numero`); Cantici and Poesie **never got that
  fix** — never delete a row, only hide via a runtime `Via` set/hardcoded exclusion list.
- `pubblica.py` uses `git worktree` (not `git stash`) specifically to avoid leaving the repo on an
  orphan branch — keep it that way.
- No lookbehind regex, no `??=`/`.at()`/`structuredClone` in app code (old iPad Safari support).
- Before adding any new top-level `const`/`function`, `grep sorgenti/` first — all files
  concatenate into one script via `costruisci.py`, a duplicate declaration kills the entire app
  silently.
- The test preview pane doesn't fire `requestAnimationFrame`/scroll events reliably when hidden,
  and renders `height:100dvh` fixed-position pages oddly sometimes — don't mistake either for a
  real app bug without checking a real device.
- `execCommand('insertOrderedList'/'insertUnorderedList')` can leave the resulting `<ol>`/`<ul>`
  invalidly nested inside a `<p>` — always route list buttons through `eseguiLista()`/`cmdLista()`
  in `5_prediche.js`, never call `execCommand` for lists directly.
- A `contenteditable` seeded with `''` behaves unpredictably (bare text nodes, Enter doesn't split
  paragraphs) — always seed with `'<p><br></p>'` at minimum.
- When parsing a contentEditable's saved HTML back into data, use `childNodes` not `children` —
  bare text nodes are invisible to `.children` and silently vanish.
- CSS custom-property scoping: redefining `--tx` etc. inside a scoped class doesn't retroactively
  fix an ancestor's already-inherited `color` — add an explicit `color: var(--tx)` on the scoping
  element itself.
- Archived Esperienze/Poesie have no `meta`-overlay system (unlike archived Prediche) — renaming
  one by editing the sheet directly silently does nothing to the card title; only the ⚙ dialog
  works. Known, accepted asymmetry, not something to unify unprompted.
- Service worker caching: a browser that visited the live site before will keep showing old
  content after a fresh publish until its service worker updates.

  already cached the old version can keep serving it for a minute or two even past cache-busting —
