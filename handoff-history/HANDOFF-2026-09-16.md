## ❌ Failed Attempts (this session)

### Interpreting "colori diversi" as title-TEXT color (v7.38, v7.39)
Twice in a row, "make the colors different per section/language" was implemented as the title's
text color rather than the card's background. Both were technically well-executed (verified with
real computed-style checks, not just screenshots) but **solved the wrong property**. Confirmed
correct only on the third attempt (v7.40), after Ovidiu explicitly said "io intendevo i colori di
sfondo della diapositiva." **Lesson**: on a small card dominated by a photo/color cover with text
overlaid on top, "the color of the card" defaults to the background in a non-technical user's
mind — don't assume text color unless they say "testo"/"scritta" explicitly. Saved as a permanent
rule in memory (`regole-lavoro-ovidiu`).

### Inventing an iPad-specific breakpoint nobody asked for (v7.39)
Added `@media(max-width:1024px)` so Poesie would show 3 columns only on tablet-width screens,
staying at 4 above that. Ovidiu's actual ask ("sempre tre in fila come le prediche") meant *always*
3, at every width — matching Prediche's plain `.g-pred` exactly, no special-casing. Removed the
whole `.g-pred4` class in v7.40; Poesie now uses literally the same grid class as Prediche.
**Lesson**: "on iPad" in one sentence doesn't necessarily scope the *whole* request to iPad only —
re-read whether the surrounding clause ("sempre", "come le prediche") implies a broader rule.

### Coordinate-based clicking on the small 📍 badge, testing v7.38
Clicking at screenshot pixel coordinates missed the button (27×20px, and the screenshot tool
scales down large viewports, so screenshot pixels ≠ CSS pixels 1:1). Wasted a couple of tries
concluding "the button doesn't work" before checking `getBoundingClientRect()` and calling
`.click()` directly on the DOM element via JS — which worked immediately and proved the button was
fine all along, the clicking method was the problem. **Lesson**: for small targets in this test
environment, verify via `.click()` on the actual element (or `read_page`/`find` refs) before
concluding a UI element is broken.

### Suspecting `autoTest()` of silently deleting user data
When "300" (a Poesia) appeared missing from Ovidiu's screenshot, briefly hypothesized that running
`autoTest()` as part of verification might have an undocumented side effect that tombstones an
item. Tested directly (`tuttePoesie().length` before/after `autoTest()`, and inspected
`stato.poeVia`): count was 4 before and after, tombstone empty both times. **Not the cause** — was
about to chase a phantom bug before this quick, cheap check ruled it out. Worth remembering:
`autoTest()` **is** observed to leave a stray value in `FE.q` (Esperienze's search box) as a side
effect of one of its 216 checks — cosmetic only, not data-touching, but clear
`localStorage`/reload after running it if you're about to leave the browser in a state Ovidiu
might see, or want a "clean" screenshot.

## ✅ Working Solutions (key decisions this session)

- **Flat CSS gradient backgrounds instead of `sfondoHtml()` on the compact card only.** The
  astronomical sky-simulation background (`sfondoHtml()`, ~22 sfondo options, used for
  projection/Home tiles/the sfondo picker) varies per individual item and can't simultaneously
  encode a consistent section+language color signal — so this one small card view stopped calling
  it, everything else that used `sfondoHtml()` before still does.
- **One shared grid class (`.g-pred`) for all three sections**, not a parametrized/special-cased
  one — simpler, and matches "sempre come le prediche" literally.
- **Light shade = Italian, dark shade = Romanian, same rule in all three section-hues** — makes
  the color code learnable as one rule ("lighter = IT, darker = RO") rather than six unrelated
  colors to memorize.
- **`numeroLuoghi(i)` reads without creating an annotation** (`stato.predAnnot[i]` accessed
  directly, not through `annot()` which lazily creates one) — safe to call on every card in a
  grid of potentially hundreds of items without bloating `stato` with empty annotation objects.
- **Rigorous verification before reporting "done" or before guessing again**: when Ovidiu pushed
  back on v7.39, checked real `getComputedStyle()` values (grid columns at 768/1400px, cover
  height, font-size, color) before touching any code — confirmed v7.39 *was* technically correct
  against its own (wrong) interpretation, which is what made it clear the problem was which
  property to color, not a bug in the color logic itself. When in doubt whether something is a
  code bug or a misunderstanding, measure first.

**GitHub Pages CDN propagation note** (hit once this session, on the v7.37 publish): right after
`pubblica.py` succeeds, a browser that already had a tab open to the live URL — or whose regional
CDN edge hasn't picked up the new push yet — can keep serving the *previous* version for a minute
or two, even with cache-busting query strings and `cache:'no-store'` fetches, because the

a direct `curl -sI` from a real terminal (bypasses any sandboxed browser tool's own network path)
and check the `last-modified`/`x-cache` headers, or `git fetch origin gh-pages` + compare the
`index.html` blob size to the local build, before concluding a publish "didn't take."

## ⚠️ Gotchas / Traps

**New this session:**
- **"Colore della carta" (the color of the card) means the BACKGROUND, not the text**, when the
  element in question is a small photo/color-dominated card with text overlaid — see Failed
  Attempts above. This is now a permanent rule in `regole-lavoro-ovidiu` memory; re-read it before
  touching any "recolor this" request on these cards again.
- **A width-only media-query breakpoint can't reliably target "iPad" as a device** — iPad portrait
  widths (744–1024px) and iPad *landscape* widths (1080–1366px) span a huge range that overlaps
  with small laptops. If a future request needs to distinguish touch tablets from desktops
  specifically, a width breakpoint alone won't be robust in both orientations — this session
  sidestepped the whole problem by dropping the tablet-specific breakpoint entirely per Ovidiu's
  final instruction ("sempre… come le prediche"), but it'll resurface if a *real* device-specific
  layout is ever requested again.
- **GitHub Pages CDN edge propagation lag** — see Dependencies & Setup above. Verify with `curl`
  from a real terminal, not just a sandboxed browser tool's preview, before concluding a publish
  failed.
- **`autoTest()` leaves a stray value in `FE` (Esperienze's filter state)** as an observed side
  effect of one of its checks — clear storage and reload after running it if the browser view
  might be shown to Ovidiu, so he doesn't see confusing leftover search text.

**Carried forward from before this session (still true — condensed; the fuller story with
photos-of-the-bug-style detail is in `programma-prediche-domande.md` and the Sept-14 handoff):**
- Positional ids (`'a'+i`, `'q'+i`) shift if you ever delete/reorder rows in the *source* JSON
  files. Prediche ids were fixed to be stable (`'pr'+numero`); Cantici and Poesie **never got that
  fix** — never delete a row, only hide via a runtime `Via` set/hardcoded exclusion list.
- `pubblica.py` uses `git worktree` (not `git stash`) specifically to avoid leaving the repo on an
  orphan branch — keep it that way.
- No lookbehind regex, no `??=`/`.at()`/`structuredClone` in app code (old iPad Safari support).
- Before adding any new top-level `const`/`function`, `grep sorgenti/` first — all files
  concatenate into one script via `costruisci.py`, a duplicate declaration kills the entire app
  silently.
- The test preview pane doesn't fire `requestAnimationFrame`/scroll events reliably when hidden,
  and renders `height:100dvh` fixed-position pages oddly sometimes — don't mistake either for a
  real app bug without checking a real device.
- `execCommand('insertOrderedList'/'insertUnorderedList')` can leave the resulting `<ol>`/`<ul>`
  invalidly nested inside a `<p>` — always route list buttons through `eseguiLista()`/`cmdLista()`
  in `5_prediche.js`, never call `execCommand` for lists directly.
- A `contenteditable` seeded with `''` behaves unpredictably (bare text nodes, Enter doesn't split
  paragraphs) — always seed with `'<p><br></p>'` at minimum.
- When parsing a contentEditable's saved HTML back into data, use `childNodes` not `children` —
  bare text nodes are invisible to `.children` and silently vanish.
- CSS custom-property scoping: redefining `--tx` etc. inside a scoped class doesn't retroactively
  fix an ancestor's already-inherited `color` — add an explicit `color: var(--tx)` on the scoping
  element itself.
- Archived Esperienze/Poesie have no `meta`-overlay system (unlike archived Prediche) — renaming
  one by editing the sheet directly silently does nothing to the card title; only the ⚙ dialog
  works. Known, accepted asymmetry, not something to unify unprompted.
- Service worker caching: a browser that visited the live site before will keep showing old
  content after a fresh publish until its service worker updates.
