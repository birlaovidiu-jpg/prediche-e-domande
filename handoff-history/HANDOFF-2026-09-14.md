## ❌ Failed Attempts (this session)

### Fixing the visual glitch when clicking bullet/numbered-list buttons
Clicking "•" or "1." in the Prediche edit toolbar made the **test preview browser pane** show a
broken/overlapping layout for a moment. Chased this for a while, found and fixed a *real* bug
along the way (see Working Solutions: list-nesting), but **the visual glitch persisted even after
that fix** — and a plain Bold click on the same paragraph never triggered it. Concluded (but did
not 100%-confirm on a real device) that this is the same class of "preview pane doesn't handle
`height:100dvh` fixed pages well" issue already documented in this project's memory from
September 11 (v7.19-20 notes) — this time seemingly triggered specifically by the DOM churn
`execCommand('insertOrderedList')` causes. **Ask Ovidiu to try a bullet/numbered list on his real
iPad** before spending more time on this — do not blindly "fix" a display issue you can't
reproduce outside one specific test tool.

### Automation quirk: standalone `key: "Return"` vs. embedded `\n` in `type`
While testing the new Cantici contentEditable fields, pressing Return as a separate key-press
action did **not** split the current paragraph (text just kept concatenating) — but typing the
exact same two lines as one string with an embedded `\n` (`"riga 1\nriga 2"`) worked perfectly
and produced two clean `<p>` elements. This looks like a quirk of the browser-automation tool used
for testing in this environment, not the app. If you're testing multi-line input in *any*
contenteditable here, use the embedded-newline form of `type`, not a separate Return keypress —
the latter gave a false negative twice before this was noticed.

### `cmd+a` to select-all inside a contentEditable during testing
Used `cmd+a` to try to clear/replace a Cantici field's content mid-test; the resulting DOM was
garbled (text got duplicated/interleaved) rather than cleanly replaced. Likely a focus-timing
issue with the automation tool, not the app. Reset via `element.innerHTML = '<p><br></p>'` (direct
DOM manipulation, fine for test purposes) instead of fighting it.

## ✅ Working Solutions (key decisions this session)

- **Reused the Prediche full-page sheet for Esperienze and Poesie** rather than building separate
  editors: extended `trovaPredica()`/`corpoPredica()`/`leggiPredica()` with `eUnEsperienza(i)`/
  `eUnaPoesia(i)` checks. All the shared machinery (rich text, `annot()`, `salvaTesto`) needed
  **zero** changes to support a third content type — it was already written generically by id.
- **Cantici stayed a small modal, not the full-page sheet** (explicit Ovidiu instruction: "lascia
  il modulo com'è, solo bianco con grigio" — then later clarified he *did* want the formatting bar
  too, just not a structural rewrite). Reused the same toolbar functions (`cmd`/`cmdVal`/
  `apriColori`/`cmdLista`/`apriMaiuscole`/etc.) inside the modal — none of them turned out to be
  hardwired to `#foglioPr` **except** the selection-size trio and image-insert, which were
  excluded rather than generalized (judged too risky to touch, see Gotchas), and `ordinaRighe`/
  `toggleSegniParagrafo`, which **were** safely generalized (see `campoScritto()`).
- **CSS custom-property scoping for the light Cantici modal** (`.foglio.chiaro { --fondo: ...; }`)
  instead of writing a parallel light stylesheet — every existing rule that already reads
  `var(--fondo)` etc. picks up the new values for free. The one trap: `color` is normally
  *inherited* from an ancestor's already-computed value, not re-resolved via `var()` at each
  descendant, so the scoping element itself needs an explicit `color: var(--tx)` — CSS variable
  redefinition alone isn't enough for properties that rely on inheritance rather than direct
  `var()` usage everywhere.
- **Cantici duplicate cleanup without touching row order**: found via three complementary checks
  (same cat+num; same first-40-chars of first strophe; same first-200-chars of all strophes
  joined, all diacritic/case-insensitive) — hid via a hardcoded id set rather than deleting rows,
  because cantici ids are positional (`'a'+arrayIndex`, baked at build time) and deleting/
  reordering would silently re-point every subsequent cantico's id (breaking music-file
  associations Ovidiu may have added). This mirrors the exact lesson already learned for Prediche
  ids (see old Gotchas below) — cantici never got the fix Prediche got (`'pr'+num`), so the same
  caution applies.
- **`plainText()`/HTML-vs-plain-text coexistence for Cantici**: rather than migrating all 1541
  untouched cantici to a new format, `str[]`/`rit` can be *either* plain text or HTML
  (`eHtml()` sniffs for a `<tag`), and every consumer (search, list preview, projection) goes
  through `plainText()` which handles both transparently. Only cantici actually re-saved through
  the new editor become HTML; everything else is untouched forever.

## ⚠️ Gotchas / Traps

**Carried forward from before this session (still true, still worth re-reading in full — this is
a condensed version, the fuller story with photos-of-the-bug-style detail is in
`programma-prediche-domande.md`):**
- Positional ids (`'a'+i`, `'q'+i` etc.) shift if you ever delete/reorder rows in the *source*
  JSON files. Prediche ids were fixed to be stable (`'pr'+numero`) after this bit Ovidiu once;
  Cantici and Poesie **never got that fix** — treat their source JSON row order as load-bearing,
  never delete a row, only hide via a runtime `Via` set/hardcoded exclusion list.
- `git stash` inside a publish script once left the repo on an orphan branch — `pubblica.py` uses
  `git worktree` instead, keep it that way.
- No lookbehind regex, no `??=`/`.at()`/`structuredClone` in app code (old iPad Safari).
- Before adding any new top-level `const`/`function`, `grep sorgenti/` first — all files
  concatenate into one script, a duplicate declaration kills the entire app silently.
- The test preview pane doesn't fire `requestAnimationFrame`/scroll events reliably when hidden,
  and renders `height:100dvh` fixed-position pages (`body.pred-fissa`/`sab-fissa`/`home-fissa`)
  oddly sometimes — don't mistake either for a real app bug without checking a real device.

**New this session:**
- **`execCommand('insertOrderedList'/'insertUnorderedList')` can leave the resulting `<ol>`/`<ul>`
  nested inside the `<p>` it replaced** (invalid HTML) instead of as a sibling. This silently
  double-counts list content in projection (`blocchiDaProiettare`/similar readers query both `p`
  and `li`). Fixed via `eseguiLista()`/`cmdLista()` in `5_prediche.js`, which unwraps the list
  after the browser command runs. **If you ever add another `execCommand`-based list button
  anywhere, route it through `eseguiLista()`, don't call `execCommand` directly.**
- **A `contenteditable` element seeded with a truly empty string (`''`) behaves unpredictably**:
  the first character typed can end up as a bare text node with no `<p>` wrapper at all, and
  Enter may not split paragraphs afterward. Always seed with `'<p><br></p>'` at minimum, mirroring
  how Prediche's `predicaVuota()` never starts from a genuinely empty sheet. This bit the new
  Cantici editor (`htmlStrofe([])` used to return `''`, now returns `'<p><br></p>'`).
- **When parsing a contentEditable's saved HTML back into structured data, don't rely solely on
  `element.children`** (element nodes only) — bare text nodes (see above) are invisible to it and
  silently vanish. `strofeDaHtml()` in `4_cantici.js` now walks `childNodes` and handles text
  nodes explicitly as a defensive measure, not just as a one-time fix.
- **CSS custom properties and `color` inheritance**: redefining `--tx` etc. inside a scoped class
  only affects descendants that *themselves* read `var(--tx)` directly — an ancestor's already
  -inherited `color` value doesn't get re-evaluated. Always add an explicit `color: var(--tx)` (or
  whichever property) on the scoping element itself when re-theming a subtree this way.
- **Archived Esperienze/Poesie have no `meta`-overlay system** (unlike archived Prediche, which
  got one specifically to fix "renaming doesn't update the card" back in v7.30). Renaming an
  archived esperienza/poesia by editing the sheet directly silently does nothing to the card
  title — only the ⚙ dialog works for those two. This is a known, accepted asymmetry, not
  something to unify unprompted (it would mean giving Esperienze/Poesie the same meta-overlay
  machinery Prediche has, a bigger change than was asked for).
- **Editing an *archived* esperienza/poesia's metadata via ⚙ forks a brand-new personal copy**
  (new id, `mia:true`) rather than annotating the original in place — same as it's always been,
  *not* touched this session despite being visibly inconsistent with how Prediche now works
  (overlay, no fork). Left alone deliberately; flagged to Ovidiu in words, not fixed.
- **Service worker caching**: a browser that visited the live site before will keep showing old
  content after a fresh publish until its service worker updates (can take a reload or two, or
  until the app's own "new version ready" prompt fires). Don't assume a publish failed just
  because a stale browser tab still shows old numbers — clear SW registrations + caches to check
  the *actual* deployed content when verifying a publish.
